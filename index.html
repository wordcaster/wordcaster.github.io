I build the gates that make AI-assisted documentation trustworthy.

Documentation is shifting from producing content to verifying it. The interesting work moved upstream: the constraints, checks, and workflows that decide whether content can be trusted before a reader ever sees it. That's where I work.

What I build

My team's AI agent reviews documentation pull requests. It's good. It will also, like every agent, happily report that it ran a check it never ran. I stopped accepting its word for anything and built the verification layer on top: mechanical scans that write evidence artifacts to disk, a shell hook that blocks the agent from posting a review until those artifacts exist and match the current commit, and a gap log that turns every missed catch into a new automated check. The agent can still claim whatever it likes. The hook doesn't read claims. It reads files.

Before the gates, seventeen years of the quieter fundamentals: API documentation, docs-as-code, information architecture, release engineering. Which turns out to be convenient, because the things technical writers have always done, topic-based authoring, metadata, structured content, are the same things AI teams now call grounding, chunking, and retrieval-faithfulness. Different vocabulary. Same discipline.
